01 — Introduction

Why distributed quantum computing?

As quantum hardware matures, the physical limits of a single Quantum Processing Unit (QPU) — qubit count, coherence time, cross-talk, cooling, wiring — make monolithic scaling increasingly difficult. Distributed Quantum Computing (DQC) connects multiple QPUs through quantum networks to form one larger computational cluster.

Programming model

NetQMPI

An MPI-inspired, backend-agnostic Python library for Distributed Quantum Computing. Following a Single-Program, Multiple-Data (SPMD) model, one script runs across N quantum nodes, coordinated through quantum-aware primitives — qsend, qrecv and quantum collectives — so entanglement, teleportation and classical messaging never need manual orchestration.

netqmpi -n 2 app.py --cunqa --shots 1024
NetQIR/netqmpi
HPC emulator

CUNQA

A Distributed Quantum Computing emulator built for HPC infrastructure. CUNQA provisions virtual QPUs (vQPUs) directly through the job scheduler (Slurm), letting you raise a multi-QPU network on a real supercomputer and model its noise and latency — the engine NetQMPI programs run on in this tutorial.

qraise -n 4 -t 01:00:00 --co-located
CESGA-Quantum-Spain/cunqa

By the end of this tutorial, you will be able to

  • Explain the bottlenecks of monolithic QPUs and the case for DQC.
  • Write distributed quantum circuits using NetQMPI's syntax and concepts.
  • Deploy, execute and profile a distributed algorithm on the CUNQA emulator.

Who this tutorial is for

Quantum software engineers, HPC researchers transitioning to quantum architectures, computer science graduate students, and computational scientists looking to future-proof their skills for the multi-QPU era.

03 — Environment Setup

Your laptop is the cluster

Every exercise runs inside a single Docker image that ships NetQMPI, the CUNQA emulator and a working Slurm installation, wired together as a miniature HPC cluster on your own machine. No supercomputer account, no VPN, no dependency hunting — install Docker, pull the image, run it.

NetQMPI The MPI-inspired library you will program with — qsend, qrecv and friends.
CUNQA The emulator that raises virtual QPUs and models the links between them.
Slurm 24.11 A real job scheduler in single-node mode: qraise provisions vQPUs just like on Qmio.
Jupyter + Python Qiskit, mpi4py and the tutorial notebooks, served to your browser on port 8888.
  1. 1

    Install Docker

    This is the only thing you install on your own system. Pick your operating system below — the whole process takes about ten minutes, most of it downloading.

    1. Docker Desktop is not required here: the Docker Engine daemon is enough, and the official script below picks the right packages for Ubuntu, Debian, Fedora, CentOS and friends.
    2. Adding yourself to the docker group lets you drop sudo. Log out and back in — or run newgrp docker — for it to take effect.
    3. The hello-world container is the standard smoke test: if it prints its greeting, the daemon is running and you are done.
    bash · any distribution 
    # 1 — install the Docker Engine
curl -fsSL https://get.docker.com | sudo sh

# 2 — use Docker without sudo (log out and back in afterwards)
sudo usermod -aG docker "$USER"

# 3 — check the installation
docker run --rm hello-world
    If your distribution ships an old docker.io package, prefer the script above — the tutorial image needs Docker 20.10 or newer.
    1. Docker on Windows runs on top of WSL 2. Open PowerShell as Administrator, run wsl --install and reboot. Windows 10 21H2+ or Windows 11 required, with virtualization enabled in the BIOS.
    2. Download Docker Desktop for Windows from docker.com and run the installer, keeping “Use WSL 2 instead of Hyper-V” ticked.
    3. Launch Docker Desktop and wait until the whale icon in the system tray reports Engine running. Leave it open: every docker command needs it.
    4. Open PowerShell (a normal one this time) and run the smoke test below.
    PowerShell · Windows 10 / 11 
    # 1 — enable WSL 2 (Administrator PowerShell), then reboot
wsl --install

# 2 — after installing Docker Desktop, check the installation
docker run --rm hello-world
    Run every command of this guide from PowerShell or from a WSL terminal — not from the old cmd.exe, which quotes arguments differently.
    1. Download Docker Desktop for Mac from docker.com, choosing the Apple silicon build on M1–M4 machines or the Intel chip build otherwise. uname -m tells you which you have: arm64 or x86_64.
    2. Open the .dmg, drag Docker into Applications, launch it and accept the privileged-helper prompt. Homebrew users can do the same with one command (below).
    3. Apple silicon only: in Settings → General, enable “Use Rosetta for x86_64/amd64 emulation”. The tutorial image is an amd64 build, and Rosetta is what makes it run at a sensible speed.
    4. Open Terminal and run the smoke test below.

  3. 3

    Start your local cluster

    One command boots munge, slurmctld, slurmd and a Jupyter server inside the container, and drops you into a shell on the head node of your very own cluster.

    terminal · start the container 
    docker run --rm -it -p 8888:8888 --name qce26 jvazquezperez/cunqa_netqmpi:latest
    Do not drop -p 8888:8888. The Jupyter server runs inside the container and listens on port 8888 there. Publishing that port is what connects it to port 8888 on your own machine; without it the container starts fine, but http://localhost:8888 stays dead and there is no way into the notebooks from your browser.

    Two variants worth knowing:

    terminal · optional variants 
    # keep your notebooks on the host after the container exits
docker run --rm -it -p 8888:8888 -v "$PWD/work:/home/tutorial/work" jvazquezperez/cunqa_netqmpi:latest

# Apple silicon (M1–M4): run the amd64 image under Rosetta
docker run --rm -it --platform linux/amd64 -p 8888:8888 jvazquezperez/cunqa_netqmpi:latest
  4. 4

    Open the notebooks and check the cluster

    On startup the container prints the address of its Jupyter server. Open it in your browser — the token is cunqa — and the tutorial notebooks are waiting for you.

05 — Code Examples

What the code actually looks like

Real, runnable snippets from the two open-source libraries — the same shape of code you'll write during the hands-on exercises.

examples/netqmpi/send_recv.py 
from netqmpi.sdk.environment import Environment

def main(env: Environment = None):
    comm = env.comm
    rank = comm.rank

    next_rank = comm.get_next_rank(rank)
    previous_rank = comm.get_prev_rank(rank)

    with comm:  # everything inside runs on the selected backend
        if rank == 0:
            circuit = env.create_circuit(num_qubits=1, num_clbits=1)
            circuit.h(0)                          # prepare |+>
            comm.qsend(circuit, [0], next_rank)   # teleport the qubit
        else:
            circuit = env.create_circuit(num_qubits=1, num_clbits=1)
            comm.qrecv(circuit, [0], previous_rank)
            circuit.measure(0, 0)

    results = comm.results
    if rank != 0:
        print(f"measure: {results}")
The programmer only calls comm.qsend() / comm.qrecv() — entanglement generation, teleportation and classical corrections are handled by whichever backend adapter you select. This exact file runs unchanged on the CUNQA backend used in this tutorial.
$ netqmpi -n 2 send_recv.py --cunqa --shots 1024 View on GitHub →
quickstart.py 
# Raising 4 virtual QPUs (vQPUs) for this job
from cunqa.qpu import qraise, get_QPUs, run
from cunqa.circuit import CunqaCircuit
from cunqa.qjob import gather

family = qraise(4, "01:00:00", simulator="Aer", co_located=True)
qpus = get_QPUs(co_located=True)

# A 2-qubit Bell circuit, sent to every vQPU
qc = CunqaCircuit(num_qubits=2)
qc.h(0)
qc.cx(0, 1)
qc.measure_all()

qjobs = run([qc] * 4, qpus, shots=1000)
results = gather(qjobs)

for r in results:
    print(f"Counts: {r.counts}")  # e.g. {'00': 512, '11': 488}
qraise provisions vQPUs straight from the Slurm job scheduler; get_QPUs hands you live handles to run circuits on. This is the emulation layer NetQMPI targets with its --cunqa backend flag.
